### 포트폴리오에서 사용할 수 있는 핵심 메시지

- 한 명을 위한 일회성 경험도 제품처럼 목표와 실패 조건을 정의했다.
- 처음부터 생일 앱임을 밝히지 않고, 관객이 복선을 직접 발견하는 구조로 바꿨다.
- 이미지 생성 결과가 의도와 어긋나자 프롬프트 반복 대신 직접 조정 가능한 콘티 편집기를 만들었다.
- 요한이 장면과 의도를 구조화하고 AI 코딩 에이전트가 구현·검증하는 협업 방식으로 전환했다.
- 재미를 위해 넣은 방해 연출에도 자비 경로를 두어 진행 불가 상태를 막았다.
- 빌드 성공과 실제 상영 성공을 분리하고 실물 노트북 리허설을 완료 조건으로 삼았다.
- 개인 사진과 캐릭터 자산이 있는 원본을 공개판과 분리한다.

### 공개 글에서 단정하면 안 되는 것

| 주장 | 이유 |
|---|---|
| 친구의 정확한 첫마디·가장 크게 반응한 장면·중간에 막힌 행동 | 세부 상황은 기록되지 않았으므로 만들지 않음 |
| 몇 시간 또는 며칠 만에 완성했다 | 시작·완료 시간을 하나의 근거로 고정하지 않음 |
| 모바일에서도 완벽하게 동작한다 | 원래 노트북 전용이며 모바일은 비목표 |
| 누구나 바로 사용할 수 있는 생일 앱 빌더다 | 공개용 빌더는 아직 설계·구현 전 |
| E2E가 정확히 12개다 | 릴리스 문서는 12개, 현재 테스트 정의는 집계 방식에 따라 13개로 보여 발행 전 재실행 필요 |
| 현재 GitHub 저장소가 오픈소스다 | visibility와 공개 안전성 모두 확정되지 않음 |
| 우사기와 개인 자산을 자유롭게 사용할 수 있다 | 공개 허용 근거 없음 |

### 공개 증거 후보

- 얼굴·실명이 없는 실물 노트북 촬영
- 커버·터미널·리듬·케이크 등 개인정보가 없는 장면의 재촬영
- 공식 14장 흐름을 개인정보 없이 다시 그린 도해
- 콘티 편집기와 AI 코딩 에이전트의 협업 방식을 보여주는 공개용 재현 화면
- 테스트·새 클론·file 실행 결과를 요약한 검증 카드
- 개인 원본과 공개용 생일 앱 빌더의 분리 구조

### 이번 회고에서 추가된 맥락

- 최초 의도는 우사기 애니메이션 → 게임 → 편지로 이어지는 생일 경험이었다.
- 요한은 AI 이미지 생성 결과가 의도와 품질에 맞지 않았고 마감 안에 완성하기 어려워 제작 방식을 바꿨다고 회고했다.
- 이 인과관계는 여러 제작 문서로 정황을 확인할 수 있지만, 글에서는 2026-08-03 요한의 직접 회고로 표현한다.
- 요한은 친구가 예상보다 크게 감동한 모습에 놀랐고, 친구는 나중에 울었다고 전했다.
- 직접 인용할 정확한 문장은 없으므로 따옴표 없이 간접 인용한다.

## 2. 우사기 Windows 세트

### 한 줄 정의

Windows의 커서·대기 애니메이션·휴지통·폴더 등에 우사기 캐릭터를 적용하고 원래 상태로 안전하게 복구하도록 만든 개인 선물용 테마 팩.

| CUR·ANI·ICO 산출물을 Windows API로 실제 로드 검증했다 | 확인됨 | `README.md` |

| 친구 사진은 공개하지 않기로 했다 | 사용자 결정 | 2026-08-03 캠페인 대화 |

### 포트폴리오에서 사용할 수 있는 핵심 메시지

- 예쁜 아이콘 제작에서 끝내지 않고 실제 Windows 형식과 적용·원복까지 완성했다.
- 릴스에서 본 커서 하나를 휴지통·폴더·작업 표시줄까지 연결된 선물 세트로 확장했다.
- 설치보다 복구를 먼저 성공 조건으로 정의했다.
- 재적용이 백업을 오염시켜 원복해도 우사기로 돌아가는 결함을 pristine 방식으로 해결했다.
- 개인 선물용 캐릭터 자산과 공개 가능한 범용 테마 엔진을 분리한다.
- 개인 전달본에서는 합성 데모를 사용해 친구 바탕화면과 파일을 노출하지 않았다. 이 데모는 우사기 파생 자산이라 공개 콘텐츠에는 사용하지 않는다.

### 공개 글에서 단정하면 안 되는 것

| 주장 | 이유 |
|---|---|
| 우사기 테마를 누구나 다운로드할 수 있다 | 개인 전달 전용이며 공개 배포 금지 |
| 공식 우사기·치이카와 제품이다 | 권리자 공식 제품이나 협업이 아님 |
| 모든 Windows 버전과 배율에서 검증됐다 | 다른 Windows 빌드·일부 배율 실기 확인이 남아 있음 |
| 친구가 어떤 항목을 계속 사용 중인지·Windows 버전이 무엇인지 | 세부 사용 환경은 아직 확인하지 않음 |
| 범용 테마 빌더가 이미 공개돼 있다 | 아직 별도 공개판 설계 전 |
| 우사기 화면은 권리 문제없이 광고·상업 콘텐츠에 사용할 수 있다 | 명시적 공식 허용 근거를 확보하지 못함 |

### 공개 증거 후보

- 개인 파일과 알림이 없는 격리 Windows 환경 재촬영
- 커서·휴지통·폴더 적용 전후의 짧은 화면
- 실제 우사기 세트의 적용·원복만 보여주는 격리 Windows 화면 녹화. 화면 노출만 허용하고 원본 파일은 배포하지 않음
- 적용 → 재적용 → 전체 원복 흐름을 설명하는 도해
- 실제 수령인 환경에서도 전체 원복을 확인했다는 요한의 회고
- 범용 도구에서 캐릭터 자산과 인코더·적용 엔진을 분리하는 구조

## 3. 두 사례를 함께 묶는 공통 이야기

두 프로젝트의 공통점은 “귀여운 결과물”보다 **실제로 전달하고 다시 원래대로 돌릴 수 있는 상태까지 책임진 것**이다.

- 생일 앱: 빌드 통과가 아니라 실물 노트북 전체 리허설이 완료 조건
- Windows 세트: 설치 성공이 아니라 전체 원복 성공이 완료 조건
- 공통: 개인 경험의 감정은 보존하되 개인정보와 캐릭터 자산은 공개판에서 분리

이 공통 이야기는 브랜드용 소개에 사용할 수 있지만, 두 프로젝트의 MDX와 쇼룸 상세는 각각 독립 사례로 만든다.
