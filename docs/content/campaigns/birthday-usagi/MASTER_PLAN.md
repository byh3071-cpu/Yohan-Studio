## 목적

개인적으로 완성한 생일 앱과 우사기 Windows 세트를 안전한 공개 사례로 전환한다. 결과물만 자랑하는 것이 아니라 문제 정의, 제작 과정, 검증, 실제 사용, 실패와 배운 점을 보여줘 Yohan Studio의 제작 역량을 증명한다.

동시에 다음 두 콘텐츠 트랙을 실전 검증한다.

1. 직접 경험형: 실물 노트북 상영, Windows 적용·원복, 실제 제작 과정
2. 긴 콘텐츠 재가공형: Studio MDX 원문을 Reel·Carousel·Threads로 변환

AI 뉴스 카드뉴스와 나머지 소재 탐색 방식은 이 캠페인의 첫 발행을 방해하지 않는 별도 실험으로 둔다.

## 확정 원칙

1. Birthday_app과 usagi-windows-theme는 개인용 원본으로 동결한다.
2. 개인용 저장소의 이름과 이미지만 지워 그대로 공개하지 않는다.
3. 공개용 앱과 도구는 개인정보·제3자 캐릭터·사적 음원이 없는 별도 저장소로 만든다.
4. 프로젝트 사실과 검증 수치는 원본 프로젝트 문서에서 확인한다.
5. 외부에 공개되는 편집 원본은 Yohan Studio MDX로 관리한다.
6. Instagram의 대표 도착지는 `https://yohanstudio.co`다. Threads는 보조 연결로 허용한다.
7. 네이버는 한국어 검색·장문 독해 가치가 있을 때만 파생한다. Instagram에서 네이버로 우회시키지 않는다.
8. Carousel은 목적·카피·와이어프레임·자산표가 확정된 뒤 이미지를 만든다.
9. 없는 GitHub 저장소·데모·다운로드·댓글 자동화는 약속하지 않는다.
10. 계정 설정 변경과 실제 발행은 사용자 최종 승인 후 진행한다.

### 2026-08-07 표시 범위 결정

- 생일 앱·우사기 세트의 Reel과 포트폴리오에서 우사기·치이카와가 화면에 보이는 문제는 이번 캠페인의 차단 조건에서 제외한다.
- 이 결정은 **화면 표시**에만 적용한다. 우사기 이미지·CUR·ANI·ICO·ZIP·개인용 저장소를 GitHub나 다운로드로 배포하는 권한까지 뜻하지 않는다.
- 개인정보는 계속 차단한다. 촬영 모드는 얼굴·실명·터미널 식별자를 가리지만 편지 본문은 유지하므로, Reel에는 편지 원문을 읽을 수 있는 프레임을 사용하지 않는다.

## 목표 산출물

### 포트폴리오

- 생일 앱 Studio MDX 원문 1개
- 우사기 Windows 세트 Studio MDX 원문 1개
- 쇼룸 사례 2개
- 각 사례의 개인정보·저작권·한계 설명

### 공개용 저장소 후보

- `birthday-app-builder`: 브라우저에서 사진·문구·장면을 로컬로 편집하고 독립 실행 HTML 또는 ZIP을 내보내는 생일 앱 빌더
- `windows-character-theme-builder`: 사용자가 가진 이미지로 CUR·ANI·ICO와 적용·원복 팩을 만드는 범용 도구

우사기 이미지, 우사기 완성 테마 ZIP, 개인 편지와 사진은 두 저장소에 포함하지 않는다.

### Instagram 첫 배치

- Reel 1: 생일 앱 실물 상영과 제작 결과
- Reel 2: 우사기 커서·휴지통·폴더의 실물 적용과 데모
- Carousel 1개: 두 원문 중 서사가 더 강한 주제를 선택해 제작기 형태로 재가공
- Threads 로그: 원문당 2~3개 후보

캐러셀과 카드뉴스는 같은 원문에서 동시에 발행하지 않는다. 경험 서사는 캐러셀, 체크리스트·방법론은 카드뉴스를 사용한다.
