# Birthday × Usagi 콘텐츠 팩트 재정비

- 날짜: 2026-08-03
- 범위: 공개 캠페인 콘텐츠 브리프·팩트 시트·쇼룸 정보 구조

## 결과

- 생일 앱 제작기의 빠진 중간 과정인 이미지 생성 한계 → 콘티 편집기 → AI 코딩 에이전트 협업을 서사의 중심에 추가했다.
- 기존 내부 제작 도구는 웹 기반 콘티·상호작용 편집기, 미래 공개판은 생일 앱 빌더로 구분했다.
- 우사기 ‘25종’을 제거하고 현재 Git 산출물 기준 최종 출력 파일 22개로 정정했다.
- 생일 앱 E2E 개수는 문서와 현재 정의 수가 달라 재실행 전까지 공개 수치에서 제외했다.
- 쇼룸을 결과 → Why → 전환점 → 선택 이유 → 증거 → 책임과 한계 순으로 재설계했다.
- 실제 친구 반응과 우사기 전체 원복 여부를 확인하는 게이트를 추가했고, 후속 확인에서 둘 다 사실을 확보했다.

후속 확인에서 생일 앱은 실제 친구에게 상영했고, 친구가 예상보다 크게 감동해 나중에 울었다고 전한 사실을 추가했다. 우사기 세트는 친구 노트북에서 전체 원복까지 확인했다. 친구 사진은 사용하지 않는다. 공개 결과는 개인정보가 없는 격리 Windows에서 새로 촬영한 실제 적용·원복 화면과 시스템 도식으로 증명하며, 캐릭터 원본 파일·설치팩·저장소·다운로드는 공개하지 않는다.

## 검증 근거

- Birthday_app의 ADR·제작 로그·콘티 편집기·최종 리허설 기록
- usagi-windows-theme의 README·CHANGELOG·dist 산출물·원복 무결성 리뷰
- 현재 yohan-studio 쇼룸 파서와 CaseStudyDetails 렌더 순서
- Nielsen Norman Group의 웹 읽기·포트폴리오 사례 자료
- W3C WAI 이미지 전달·대체 텍스트 자료

## 교훈

README나 과거 로그에 적힌 개수는 사실의 정본이 아니다. 파일 수·테스트 수처럼 코드와 산출물에서 파생되는 값은 발행 직전에 현재 상태에서 다시 계산해야 한다. 숫자가 제목과 핵심 주장에 들어갈수록 검증 책임이 커진다.

개인 프로젝트의 후기는 기술 검증과 별개의 증거다. 리허설 성공만으로 실제 친구 반응이나 실사용을 추정하지 않고 당사자의 기억을 따로 확인한다. 사진은 필수 증거가 아니며, 사용할 때만 별도 동의를 받는다.

## 역전파

- 범용 수치 드리프트 방지 규칙을 `docs/patterns/docs-derived-count-drift.md`에 기록했다.
- 콘텐츠 브리프와 팩트 시트에서 25종·E2E 12개 단정을 제거했다.
- 마스터 플랜에 실제 반응·전체 원복 확인 결과와 친구 사진 미사용 결정을 반영했다.
