### `/$` · `/&` 의 정체 — React 내부 구조물 (2026-07-28 확정)

당초 "라이브 스캔에서 깨진 `href` 0건 → 과거 잔재 추정"이라고 적었으나 **틀렸다.** `href` 만 봐서 못 찾은 것이고, 잔재가 아니라 **지금도 계속 생성되고 있다.**

React는 스트리밍 SSR에서 Suspense 경계를 **HTML 주석 노드**로 표시한다. React DOM 하이드레이션 코드가 그 마커를 읽는 부분:

```js
// .next/static/chunks/*.js
if ("/$" === (n = a.data) || "/&" === n) { ... }   // a.data = 주석 노드 내용
```

라이브 실측(2026-07-28):

| 라우트 | `<!--$-->` | `<!--/$-->` |
|---|---|---|
| `/` | 2 | 2 |
| `/blog` | 2 | 3 |
| `/updates` | 2 | 3 |
| `/showroom` | 2 | 3 |
| `/store` | 2 | 2 |
| `/diagnosis` | 2 | 2 |

구글의 URL 추출기가 이 주석 내용(또는 JS 청크의 문자열 리터럴 `"/$"`·`"/&"`)을 **상대 경로로 오인**해 `https://yohanstudio.co/$` 로 해석한 것이다.

**둘 중 어느 경로인지는 구분 못 한다** — 주석에서 주웠는지 JS 파일에서 주웠는지. 구글은 양쪽 다 하고 우리 쪽엔 양쪽 다 있다. 구분하려면 GSC URL 검사의 "참조 페이지"가 필요하다.

**결론**: Next.js App Router + Suspense 를 쓰는 한 없앨 수 없는 **영구 오탐**이다. GSC 404 카운트는 앞으로도 2 밑으로 안 내려간다. 404는 구글 공식 입장상 순위에 해가 되지 않으므로 무시한다.

> ⚠️ 다음에 GSC 404 알림이 오면 이 절을 먼저 볼 것. `/$`·`/&` 는 재조사 금지.

## E. ★ D1(canonical 오염) 판정 정정

당초 "대체 페이지 3건 = canonical 오염 라우트 3장" 이라는 정황으로 **"이미 3장이 색인에서 제외됐다"** 고 판단했다. **틀렸다.** 대체 페이지 3건은 `/contact?service=*` 였고, 이는 정상 동작이다. 3=3은 우연이었다.

미색인 17건 전수 확인 결과 `/blog`·`/updates`·`/showroom` 은 **어디에도 없다.** 즉 셋 다 색인 28건 안에 정상적으로 들어 있다.

| | 코드 검토 시 판정 | 필드 데이터 확인 후 |
|---|---|---|
| D1 실재 여부 | 사실 | **사실 (변함없음)** |
| D1 현재 피해 | "3장 색인 제외 중" | **피해 없음. 구글이 canonical 선언을 따르지 않고 있음** |
| D1 성격 | 진행 중 사고 | **잠재 위험** |
| 심각도 | 최상 | **상** |

구글은 canonical을 명령이 아니라 힌트로 취급한다. 페이지 내용이 홈과 명백히 다르니 자체 판단으로 self-canonical 처리한 것으로 보인다.

**그래도 고쳐야 하는 이유 3가지**
1. 구글이 언제든 우리 선언을 따를 수 있다 — 지금 안 따르는 건 보장이 아니다
2. 네이버·빙은 다르게 반응할 수 있다
3. 명백히 틀린 신호를 스스로 보내고 있다

**상대적으로 D2(백지 목록)가 더 실질적인 피해다.** `/blog` 는 색인돼 있는데 노출이 0이다. 색인이 됐어도 매칭될 내용이 HTML에 없다.
