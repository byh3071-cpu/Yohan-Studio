# Yohan Instagram Cardnews

원문 하나를 게시 가능한 인스타그램 캐러셀로 만든다. 제작, 외부 자동화, 승인본 보관을 한 단계로 섞지 않는다.

## 안전 경계

- `Go Live`, 게시, 실제 DM 발송은 명시적 사용자 승인 전 실행하지 않는다.
- 작업본은 현재 작업공간에 두고, 승인본만 Yohan Studio에 보관한다.
- 제품 명령어·모델명·요금제·UI 제약처럼 변할 수 있는 사실은 공식 최신 출처 또는 실제 UI로 다시 확인한다.
- 이미지 생성 결과의 한글 타이포를 최종본으로 사용하지 않는다. 비주얼과 정확한 조판을 분리한다.
- 원본 이미지 비율을 유지한다. 너비·높이를 따로 늘려 찌그러뜨리지 않는다.
- 한 번 승인된 디자인을 브랜드 기본값으로 자동 승격하지 않는다.
- 승인 뒤 사실·명령어 결함이 발견되면 해당 디자인 인텔리전스를 즉시 `superseded`로 강등하고 재사용하지 않는다. 기존 파일은 덮어쓰지 않고 교정본을 새 revision으로 만든다.

## 1. 콘텐츠 계약 정의

다음을 먼저 추출하거나 확인한다.

- 독자가 얻을 결과 한 문장
- 대상 독자와 사전 지식
- 카드 수와 카드별 역할
- 댓글 키워드와 전달할 DM 내용
- 필수 명령어·링크·주의사항·출처
- 현재 요청 단계: 초안, 디자인 검토, 최종 내보내기, 자동화 설정, 보관

불안정하거나 영향이 큰 주장은 디자인 전에 검증한다. 확인하지 못한 주장은 사실처럼 단정하지 않는다.

명령어·플래그·설치 절차가 들어가면 홍보 문구나 이전 카드뉴스를 근거로 재사용하지 않는다. 현재 공식 문서와 원본 저장소를 읽고, 가능한 경우 설치된 CLI의 `--help` 또는 읽기 전용 검사 명령으로 실제 표면을 확인한다. `-e`, `max`처럼 짧은 토큰의 의미를 추정하지 않는다. 검증한 버전·날짜·출처를 `design-generation-notes.md`에 남긴다.

Yohan Studio 블로그 MDX에서 파생하는 작업이면 yohan-brain `memory/rules/content-platform-specs/instagram-cardnews.md`와 `instagram-carousel.md`를 읽는다. 방법론·리스트는 카드뉴스, 경험·회고는 서사형 캐러셀로 분기하고 동일 마스터에서 둘을 중복 발행하지 않는다. 서사형이면 이 스킬에서 멈추고 해당 캐러셀 흐름으로 라우팅한다.

## 2. 카드 흐름 설계

기본 서사를 주제에 맞게 줄이거나 바꾼다.

1. 표지: 한 가지 결과 약속
2. 개념: 헷갈리는 용어 구분
3. 흐름: 역할과 순서
4. 행동: 설치 또는 첫 단계
5. 필수 문장·설정
6. 상세 설정
7. 제한과 주의사항
8. CTA: 댓글 키워드와 받을 내용

계정 브리프에 다른 문체가 없으면 존댓말을 사용한다. 카드에서 읽히지 않을 출처 URL과 보조 문구는 캡션 또는 DM으로 옮긴다.

## 3. 시각 시스템 설정

- 정적 그래픽 제작 전 현재 클라이언트가 제공하는 `canvas-design` 계열 스킬을 읽는다. 없으면 `design-philosophy.md`부터 작성한다.
- `docs/content/DESIGN-ARCHIVE.md`와 최근 승인본의 `design-intelligence.yaml`을 읽는다.
- 승인본에서 재사용할 요소와 이번 주제에만 해당하는 요소를 구분한다.
- 기본 캔버스는 `1080×1350`, RGB PNG, 4:5로 만든다.
- 핵심 콘텐츠는 좌우 76px 이상 안쪽에 두고, 핵심 텍스트·로고는 중앙 `1080×1080` 영역(세로 135~1215px) 안에 둔다.
- 이미지 생성은 분위기·오브젝트·추상 구조에 사용하고, 한글·명령어·번호·정렬은 결정론적으로 조판한다.
- 반복 패널은 동일한 간격, 모서리, 내부 정렬 규칙을 사용한다.
- 작게 꾸미는 대신 중요하지 않은 라벨을 제거한다.

### 모바일 가독성 시작 기준

- 주 제목: 60px 이상
- 핵심 본문: 28px 이상
- 패널 본문: 26~28px 이상
- 명령어: 29px 이상, 의미 단위로 줄바꿈
- 번호 원: 50px 이상, 숫자 23px 이상
- 핵심 정보에 얇은 글꼴을 사용하지 않는다.

숫자 기준만으로 통과시키지 않는다. 축소본과 실제 인스타 편집 화면이 최종 판정 근거다.

## 4. 두 번에 나눠 제작

### A. 구조 패스

- 전체 카드와 미리보기 한 장을 만든다.
- 서사 순서, 용어, 사실, 시각 위계를 확인한다.
- 생성 원본과 조판된 최종 PNG를 분리한다.

### B. 완성도 패스

- 렌더된 글자 경계를 기준으로 행간과 수직 정렬을 맞춘다.
- 번호·아이콘·여러 줄 텍스트를 전체 블록 높이로 가운데 정렬한다.
- 반복 패널의 내부 여백을 대조한다.
- 비율 유지 리사이즈 뒤에만 약한 선명화를 적용한다.
- 장식을 추가하기 전에 기존 요소의 크기·간격·대비를 개선한다.

## 5. 인스타 축소 크기로 검수

원본만 보고 승인하지 않는다.

1. 다음 명령으로 규격을 검사하고 50% 축소본을 만든다.

```powershell
node skills/yohan-instagram-cardnews/scripts/validate-carousel.mjs --input <PNG 폴더>
```

2. 원본 PNG와 `preview-instagram-scale.png`를 모두 눈으로 확인한다.
3. `references/review-rubric.md`에 따라 PASS/FAIL을 판정한다.
4. 사용자가 실제 인스타 편집 화면을 보내면 데스크톱 미리보기보다 강한 증거로 취급한다.

## 6. 댓글→DM은 선택 단계로 준비

카드뉴스마다 자동화가 필요한 것은 아니다. 요청된 경우에만 다음 문구를 먼저 만든다.

- 캡션 CTA
- 공개 댓글 답변 2~3개
- 버튼 하나가 있는 첫 DM
- 약속한 명령어·링크·주의사항을 담은 후속 DM
- 소유자 또는 지정 테스트 계정용 점검 목록

ManyChat 연결 계정·권한·트리거·요금제 조건을 실제 UI 또는 공식 최신 문서에서 확인한다. 첫 검증은 특정 게시물과 테스트 댓글로 제한한다. 사용자 승인 전 자동화를 초안 상태로 유지한다.

## 7. 반복 학습과 승격

각 제작 뒤 `design-generation-notes.md`에 수정 요청을 다음 범주로 기록한다.

- 사실·용어
- 문체·CTA
- 글자 크기·행간
- 정렬·여백
- 이미지 비율·선명도
- 실제 인스타 화면에서만 발견된 문제

승격 단계를 구분한다.

- 한 게시물 승인: 해당 게시물의 `golden_candidate`
- 서로 다른 게시물에서 반복 성공: 재사용 패턴 후보
- 사용자 승인: Yohan Studio 기본 규칙 또는 Brain 색인 대상

반복 성공 전에는 특정 색상·우주 이미지·카드 수를 전역 취향으로 일반화하지 않는다.

## 8. 승인 뒤 보관

`docs/content/DESIGN-ARCHIVE.md`를 기준으로 다음 구조에 보관한다.

```text
docs/content/exports/<slug>/
├─ instagram-cardnews.md
├─ design-philosophy.md
├─ design-generation-notes.md
├─ design-intelligence.yaml
└─ assets/
   ├─ final/
   └─ source/
```

기존 slug를 덮어쓰지 않는다. 승인된 최종 PNG·미리보기·생성 원본·프롬프트·상대경로·해시를 보존한다. 거절된 시안은 비교 근거로 별도 승인된 경우에만 variants로 남긴다.

보관 뒤 결함이 발견된 경우에는 기존 slug의 메타데이터만 `superseded`로 바꾸고 이유를 남긴다. 교정된 PNG는 사용자 재승인 뒤 새 revision slug로 보관한다.

## 산출물

- 번호가 붙은 최종 PNG
- 전체 흐름 미리보기
- 50% 인스타 축소 검토본
- 캡션과 선택적 ManyChat 문구
- 디자인 철학과 생성·수정 기록
- 보관 상태: 작업본 / 승인·미보관 / 보관 완료

최종 보고는 준비된 결과부터 말하고 절대경로 링크를 제공한다. 실제 플랫폼에서만 확인 가능한 항목은 별도로 명시한다.
