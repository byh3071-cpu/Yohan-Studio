> **한눈에 요약**
> Luna는 작업에 쓰는 모델이고 Max는 추론 강도다. Sol Advisor는 Sol이 설계와 검증을 맡고, 별도로 만든 Luna 작업이 구현하도록 연결하는 커뮤니티 플러그인이다. 다만 2026년 8월 14일 기준 Windows에서는 원본 `main`의 권한 판별 오류가 해결되기 전까지 최초 설정이 막힐 수 있다.

먼저 선을 긋자. **Sol Advisor는 OpenAI 공식 기능이 아니라 공개된 커뮤니티 플러그인**이다. 특정 계정 전용은 아니지만, 설치했다고 모든 환경에서 Luna/Max가 자동으로 켜지는 것도 아니다.

내 Windows 환경에서는 수정 패치를 적용한 뒤 설정 상태 `ready`, 구성 검사 `valid`, Luna/Max 작업 생성부터 대기·결과 읽기까지 확인했다. 반대로 공개 원본의 Windows 오류도 재현했다. 그래서 아래 가이드는 확인된 사용 구조와 아직 남은 제한을 분리해서 적는다.

## Luna, Max, 작업 경로는 각각 무엇인가?

세 용어는 서로 다른 층이다.

- **Luna**: 실제 구현 작업을 맡는 모델 `gpt-5.6-luna`
- **Max**: Luna 작업을 만들 때 함께 지정하는 추론 강도
- **Luna 작업 경로(task lane)**: Sol이 현재 대화에서 설계하고, 별도 Codex 작업에 Luna/Max를 지정해 일을 보낸 뒤 결과를 다시 검토하는 흐름

여기서 Luna 작업은 일반적인 Codex 네이티브 서브에이전트가 아니다. 사용자가 사이드바에서 볼 수 있는 별도 작업으로 생성된다. 그래서 플러그인은 이 경로를 임의로 켜지 않고, **사용할 요청마다 다시 승인**하게 되어 있다.

## 설치 전에 무엇이 필요한가?

Luna/Max 작업 경로에는 다음 네 가지가 필요하다.

1. Agent Plugins v1을 지원하는 Codex
2. Bun 런타임
3. 계정의 GPT-5.6 Luna와 Max 추론 사용 권한
4. Codex 앱의 작업 생성·대기·읽기 도구

Luna나 Max, 필요한 작업 도구 중 하나라도 없으면 다른 모델로 자동 대체하지 않고 중단한다. 이 실패 차단 방식은 플러그인의 의도된 동작이다.

설치 명령은 터미널에서 실행하지만, **이 글의 Luna/Max 흐름은 Codex 데스크톱 앱을 기준으로 확인했다.** CLI 단독 실행, VS Code 확장, Cursor의 Luna 작업 경로까지 같은 동작이라고 주장하지 않는다.

## 1단계: 운영체제에 맞게 Bun 설치하기

Windows PowerShell에서는 다음 명령을 실행한다.

```powershell
powershell -c "irm bun.sh/install.ps1|iex"
```

macOS와 Linux에서는 다음 명령을 실행한다.

```bash
curl -fsSL https://bun.com/install | bash
```

설치 뒤에는 **새 터미널**을 열고 확인한다.

```text
bun --version
```

Windows에서 설치 파일은 있는데 `bun` 명령만 인식하지 못하면 PATH 문제일 가능성이 크다. [Bun 공식 설치 문서](https://bun.sh/docs/installation)의 Windows PATH 절차를 적용하고, Codex 앱도 완전히 종료한 뒤 다시 연다.

## 2단계: Sol Advisor 등록하기

Codex 터미널에서 저장소 마켓플레이스를 추가하고 플러그인을 설치한다.

```text
codex plugin marketplace add DannyMac180/sol-advisor --ref main
codex plugin add sol-advisor@sol-advisor
```

Windows PowerShell에서 실행 정책 때문에 `codex.ps1` 오류가 뜨는 환경이라면 같은 명령의 `codex`만 `codex.cmd`로 바꿔 실행한다.

설치 뒤에는 Codex 앱을 완전히 종료하고 다시 연 다음 **새 채팅**을 만든다. 오래 열린 채팅은 새로 추가된 작업 도구 목록을 그대로 반영하지 못할 수 있다.

## 3단계: Luna/Max 논리 설정 저장하기

플러그인 설치는 모델을 고르거나 설정을 저장하지 않는다. 새 채팅에서 다음처럼 최초 설정을 요청한다.

```text
Use $sol-advisor:setup in this parent chat.
Use Codex project scope.
Enable the separate Luna/Max app-task lane.
Save logical preferences only.
Do not render or install native adapters.
Ask me for the exact model IDs shown in /model.
```

모든 프로젝트에서 같은 설정을 쓰고 싶다면 `project scope`를 `user scope`로 바꾼다. 사용자 범위는 전역 파일에 영향을 줄 수 있어 별도 동의가 한 번 더 필요하다.

설정 중에는 Codex의 모델 선택기나 `/model`에 실제로 표시되는 모델 ID를 그대로 복사해야 한다. 플러그인의 현재 권장값은 일반 구현 `gpt-5.6-terra`/High, 복잡한 구현 `gpt-5.6-terra`/High, 검토 `gpt-5.6-sol`/High다. 이는 권장값일 뿐, 플러그인이 존재하지 않는 모델을 추측하거나 대신 골라주지는 않는다.

Luna 전용으로 쓰더라도 이 논리 설정은 필요하다. 대신 네이티브 호환 역할을 설치하는 `scripts/install-agents.sh`는 실행하지 않아도 된다. 그 스크립트는 별도의 Terra → Sol 네이티브 작업 경로를 쓸 때 필요한 것이다.

## 4단계: 요청마다 Luna 작업 경로 승인하기

실제 기능 요청에는 승인 문장을 함께 넣는다.

```text
Use $sol-advisor:orchestration for this feature.
Use the Luna task lane for this feature.

[여기에 만들 기능과 완료 조건을 적습니다.]
```

핵심은 두 번째 문장이다. 이전 요청에서 한 번 승인했더라도 다음 요청에 자동으로 이어지지 않는다. Luna 작업이 만들어지면 Codex 앱에서 별도 작업과 그 상태를 볼 수 있어야 한다.

## 제대로 연결됐는지 어떻게 확인하나?

설치 완료 문구만으로 판단하지 않는다. 새 채팅에서 다음 네 가지를 확인한다.

1. Sol Advisor의 `get_setup_status`가 `ready`를 반환한다.
2. `validate_configuration`이 유효한 설정으로 판정한다.
3. Luna 요청 시 별도 Codex 작업이 생성된다.
4. 생성 정보에서 Luna와 Max가 확인되고, 작업 완료 뒤 결과를 다시 읽어 검토한다.

내 로컬 점검에서는 2026년 8월 13일 수정된 Windows 빌드로 `create → wait → read` 흐름과 `gpt-5.6-luna`/Max를 확인했다. 다만 이것은 **수정 패치를 적용한 환경의 결과**다. 아래 공개 원본의 Windows 제한과 섞어 읽으면 안 된다.

## Windows에서는 왜 바로 안 될 수 있나?

2026년 8월 14일 기준 공개 원본 v0.5.0에는 Windows의 비공개 폴더 권한을 POSIX 권한 비트처럼 판별하는 문제가 남아 있다. 그 결과 Bun이 제한된 폴더도 `0666`으로 보고해 `get_setup_status`와 `save_preferences`가 거부될 수 있다.

- [Windows 이슈 #20](https://github.com/DannyMac180/sol-advisor/issues/20): 열림
- [Windows 수정 PR #22](https://github.com/DannyMac180/sol-advisor/pull/22): 열림

이때 폴더 보안 검사를 끄거나 권한을 무리하게 풀어 우회하면 안 된다. PR #22가 병합된 뒤 마켓플레이스를 갱신하는 편이 안전하다.

```text
codex plugin marketplace upgrade sol-advisor
codex plugin add sol-advisor@sol-advisor
```

`bun`은 정상인데 Luna 작업에 필요한 도구 하나만 보이지 않는다면 앱을 완전히 종료한 뒤 새 채팅에서 다시 확인한다. 그래도 필요한 도구가 모두 노출되지 않으면 해당 환경에서는 Luna 경로를 중단해야 한다.

## 운영체제와 앱별로 어디까지 같은가?

- **Windows**: Bun과 플러그인 등록 명령은 확인했다. 공개 원본의 최초 설정은 이슈 #20 때문에 막힐 수 있다.
- **macOS·Linux**: 공식 Bun 설치 명령과 Sol Advisor의 공통 Codex 설치 명령을 사용할 수 있다. 이번 작업에서 실제 기기 스모크 테스트까지 하지는 않았다.
- **Codex CLI**: 플러그인 등록 명령을 실행하는 통로로 쓸 수 있다. Luna/Max 별도 작업의 실제 운영은 Codex 앱 작업 도구가 필요하다.
- **VS Code·Cursor 등**: Sol Advisor에는 별도 네이티브 어댑터 경로가 있지만, 이 글의 Luna/Max 작업 경로와는 다른 기능이다.

정리하면, 설치 명령 두 줄보다 중요한 건 **현재 환경의 기능 노출을 실제로 확인하는 것**이다. 공개 원본의 최신 상태는 [Sol Advisor 저장소](https://github.com/DannyMac180/sol-advisor)에서 확인할 수 있다.
